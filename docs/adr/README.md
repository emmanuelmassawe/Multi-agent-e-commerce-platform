# Architecture Decision Records

Use the MADR template in `0000-template.md` for decisions that affect the stack, API, data strategy, security, or agent topology.

1. Identify the decision and why it is needed now.
2. List decision drivers and at least two options.
3. Gather reproducible evidence. Never invent benchmark or cost numbers; write **not measured yet** when evidence is unavailable.
4. Draft with status `proposed`.
5. Review the options and record dissent.
6. Mark `accepted` before implementation and link the ADR from relevant code and docs.
7. Supersede, never delete, an old decision.

Phase 0 records the stack directions already supplied in project instructions as proposed ADRs. They remain unaccepted pending review and product context.
